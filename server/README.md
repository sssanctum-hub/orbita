# Сервер аккаунтов — прототип

Размещение: виртуальная машина Yandex Compute Cloud, Docker, постоянный диск /data. Не размещать SQLite в эфемерном контейнере Cloud Functions.

Сборка: docker build -t orbita-accounts server
Запуск: docker run -d --restart unless-stopped -p 127.0.0.1:8080:8080 -v orbita-data:/data -e ALLOWED_ORIGINS=https://ВАШ-САЙТ orbita-accounts

Поставить Caddy/nginx перед портом 8080 с HTTPS на собственном api-домене. Открыть 443; порт 8080 наружу не открывать. Настроить резервные копии SQLite через sqlite backup, не копировать живой файл отдельно от WAL.

В frontend задать VITE_ACCOUNT_API=https://api.ВАШ-ДОМЕН перед npm run build. Секретов в frontend нет. Разрешённые origins перечисляются через запятую; origin Android нужно проверить на устройстве перед добавлением.

Текущее состояние: регистрация, вход, отзыв сессии, ручной обмен полной копией с контролем облачной ревизии. Токен хранится только в памяти, после перезапуска нужно войти. Автоматической синхронизации и объединения изменений нет. Локальные данные остаются после выхода — на общем устройстве это нужно учитывать.

До публичного запуска необходимы подтверждение почты и восстановление пароля, постоянное ограничение попыток на reverse proxy, асинхронное хеширование паролей/защита от нагрузки, лимиты диска, проверка схемы записей, политика удаления аккаунтов и испытания Android/iPhone. Текущая версия для закрытого тестирования, не для публичной регистрации.

## Обновление аккаунтов
Сервер теперь требует ACCOUNT_STORAGE_KEY: 32 случайных байта в hex, хранить отдельно от SQLite и резервировать в защищённом хранилище. Почта хранится зашифрованной AES-GCM, поиск выполняется по HMAC. Записи и фотографии принимаются только как зашифрованный клиентом контейнер. Исходный пароль на сервер не отправляется. Старый формат аккаунтов автоматически не мигрирует.
